# Usage

## Install

Python 3.10 or later.

```bash
python3 -m pip install -r requirements.txt     # pandas, duckdb, openpyxl, requests, pytest
# or, as a package with the `ttc-delay` command:
python3 -m pip install -e ".[dev]"
```

## Commands

```bash
python3 -m ttc_delay run --sample  # offline, on data/sample/
python3 -m ttc_delay all           # download every file via the CKAN API, then run
python3 -m ttc_delay download      # only download: files and manifest.json go to data/raw/
python3 -m ttc_delay run           # only run, on files already in data/raw/
```

Options:

| Option | Commands | Meaning |
|---|---|---|
| `--raw-dir PATH` | all | where the source files are (default `data/raw/`) |
| `--force` | download | re-download files that already exist |
| `--sample` | run, all | use the committed sample in `data/sample/` |
| `--db PATH` | run, all | DuckDB file (default `data/warehouse/ttc_delay.duckdb`) |
| `--reports-dir PATH` | run, all | reports folder (default `reports/`) |
| `--export-dir PATH` | run, all | Power BI CSV exports (default `data/export/`) |

The run exits with status 1 if a hard data-quality check fails.

## Outputs

Real data:

- warehouse: `data/warehouse/ttc_delay.duckdb`
- reports: `reports/` (data quality, KPI summary, station matching and the list of unmatched station names)
- Power BI exports: `data/export/*.csv`

Sample run: the same files under `data/sample_build/` (`ttc_delay.duckdb`, `reports/`, `export/`).

`reports/kpi_summary.md` collects the headline tables, and `FINDINGS.md` explains them for non-technical readers.

## Charts

`tools/plot_views.py` reads `data/export/` and writes `docs/cause-pareto.png` and `docs/station-ranking.png`. Run it after the real-data run. It needs matplotlib, which is not in `requirements.txt`.

```bash
python3 -m pip install matplotlib
python3 tools/plot_views.py
```

## Example queries

Which causes cost Line 2 the most minutes in 2024, and how few of them make up 80%?

```python
import duckdb
con = duckdb.connect("data/warehouse/ttc_delay.duckdb", read_only=True)
con.sql("""
    SELECT minutes_rank, cause_code, cause_description, delay_minutes,
           round(share_of_minutes, 3) AS share_pct, round(cumulative_share, 3) AS cumulative, in_pareto_80
    FROM kpi_cause
    WHERE line_scope = 'BD' AND year_scope = '2024'
    ORDER BY minutes_rank LIMIT 10
""").show()
con.sql("SELECT * FROM kpi_pareto WHERE line_scope = 'BD' AND year_scope = '2024'").show()
```

Which stations lose the most minutes per incident once small samples are allowed for?

```python
con.sql("""
    SELECT shrunk_rank, naive_rank, station_label, incidents,
           round(naive_minutes_per_incident, 2) AS naive, round(shrunk_minutes_per_incident, 2) AS shrunk,
           explanation
    FROM station_ranking WHERE period = 'Last 36 months' ORDER BY shrunk_rank LIMIT 10
""").show(max_width=250)
```

The `explanation` column says why a station moved between the naive and the shrunk ranking, for example: "Rose 13 places: shrinkage moved its rate +0.43 min; only 240 incidents, so 38% of its gap to the line rate (3.12 min) is treated as noise."

## Power BI report

1. Run the pipeline (real data or `--sample`) so the CSV exports exist.
2. Open `powerbi/TTCDelay.pbip` in Power BI Desktop (Windows). Older versions need these preview features turned on: Power BI Project (.pbip) save option, Store semantic model using TMDL format, and Store reports using enhanced metadata format (PBIR).
3. Go to Transform data, then Edit parameters, and set `DataFolder` to the absolute path of the export folder, for example `C:\ttc-delay-analysis\data\export`. Then select Refresh.

Pages:

- Overview: KPI cards, delay minutes by month and by line.
- Cause Pareto: minutes by cause with a cumulative-share line, "causes to 80%" cards and a ranked cause table.
- Station Ranking: a period slicer (the ranking measures show "All years" until one period is selected), naive and shrunk rates and ranks, the shrinkage weight, the explanation, a naive-versus-shrunk scatter and a rank-change chart.
- Trend: rolling 12-month minutes by line, MoM and YoY measures, and cause-category shares by year.

The project is committed as text and generated by `tools/build_pbip.py` from one spec (tables, measures, visuals). Edit the spec and rerun it rather than editing the files by hand.

## Repository layout

```
ttc_delay/     ETL, warehouse loader, data-quality checks, ranking, summary, CLI
sql/           schema.sql, kpis.sql, ranking.sql
reference/     stations, lines, curated station aliases, fuzzy-match review decisions
data/sample/   every 25th row of each real source file (offline runs and tests)
reports/       outputs of the real-data run
powerbi/       TTCDelay.pbip, semantic model (TMDL), report (PBIR)
tools/         build_pbip.py, check_pbip.py, make_sample.py, plot_views.py
tests/         pytest suite, hand-computed datasets and values
```
